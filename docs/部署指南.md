# 金融学院 AI Agent 部署指南

仓库由 FastAPI 后端、React/Vite 前端和 Nginx 前端容器组成。推荐 Docker Compose 部署；前端的 `/api/` 请求由容器内 Nginx 转发给后端。仓库根目录 `.env` 是 Compose 的变量来源，更新后的 Compose 会把 MiniMax 配置传给后端，并把 SQLite 文件写入持久化的 `data/` 目录。

## 1. 部署前准备

- Docker Engine + Docker Compose v2；在本机开发时可用 Python 3.11+、Node.js 20。
- 有效的 MiniMax API Key；没有密钥时健康检查可用，但 AI 请求会失败。
- 服务器端口 80（或由反向代理接入），对外上线建议配置域名和 HTTPS。

```text
浏览器 → :80 前端 Nginx → /api/ → FastAPI :8000 → MiniMax / 数据服务
                                      └→ /app/data/finance_agent.db
```

## 2. Docker Compose 启动

```bash
git clone https://github.com/1828703450qqcom-ux/finance-academy-agent.git
cd finance-academy-agent
cp .env.example .env
# 编辑 .env，填入真实 MINIMAX_API_KEY；不要提交该文件
docker compose config
docker compose up -d --build
docker compose ps
```

浏览器访问 `http://服务器地址/`；API 健康检查为 `http://服务器地址/api/health`，API 文档为 `http://服务器地址/docs` **不经前端 Nginx 代理**，开发时可以通过本机的 `http://127.0.0.1:8000/docs` 查看。服务器对外发布时，不建议直接开放 8000 端口。

Windows PowerShell 将 `cp .env.example .env` 换成 `Copy-Item .env.example .env`。若 80 端口已占用，修改 `docker-compose.yml` 中前端的宿主机端口映射，例如 `8080:80`，然后访问 `http://localhost:8080/`。

## 3. 本机开发

在第一个终端：

```bash
cd backend
python -m venv .venv
# Windows: .venv\Scripts\activate
. .venv/bin/activate
python -m pip install -r requirements.txt
# Linux/macOS：把仓库根目录 .env 中的变量导入当前 shell，或手动设置 MINIMAX_API_KEY
uvicorn main:app --host 127.0.0.1 --port 8000 --reload
```

在第二个终端：

```bash
cd frontend
npm install
npm run dev
```

访问 Vite 输出的本地地址（通常 `http://localhost:5173`）。本地开发时不要把 API Key 写入 `frontend/` 或以 `VITE_` 前缀公开到浏览器。

## 4. 线上反向代理与访问控制

Compose 默认提供前端 80 端口；后端端口已限制为宿主机 `127.0.0.1:8000`。如需 HTTPS，可在服务器上用 Nginx/Caddy 代理前端容器的本机端口，并安装可信证书。公网仅开放 80/443；不要暴露数据库文件、上传目录和 `.env`。当前代码尚未提供通用账号权限控制，上线前应根据使用场景增加访问限制。

## 5. 验收、持久化与更新

```bash
curl http://127.0.0.1/api/health
docker compose logs --tail=100 backend
docker compose logs --tail=100 frontend
```

Compose 将 `./data` 挂到后端 `/app/data`，数据库路径由 `FINANCE_DB_PATH=/app/data/finance_agent.db` 指定；`./uploads` 挂到 `/app/uploads`。备份时保存仓库根目录 `data/`、`uploads/` 和服务器端的 `.env`（密钥需加密保存）。更新前先备份，再运行 `git pull && docker compose up -d --build`，随后复查健康接口和主要 AI 页面。回滚时用上一个 Git 提交重建镜像，并恢复对应的数据备份。

## 6. 常见问题

| 现象 | 处理 |
|---|---|
| 容器正常但 AI 报密钥错误 | 检查根目录 `.env` 的 `MINIMAX_API_KEY`，执行 `docker compose up -d --force-recreate backend`。 |
| `/api/health` 502 | 检查 `docker compose ps`、后端日志和前端 `nginx.conf` 的代理地址。 |
| 重建后聊天历史消失 | 确认使用新版 Compose 和 `FINANCE_DB_PATH`，检查 `data/finance_agent.db`。旧版镜像中未挂载的数据库需在清理旧容器前单独导出。 |
| 宿主机 80 端口冲突 | 修改前端端口映射，或让已有反向代理转发到本机可用端口。 |

数据接口可能依赖第三方服务，实际可用性与数据源网络状态有关；金融分析结果需要人工复核。
